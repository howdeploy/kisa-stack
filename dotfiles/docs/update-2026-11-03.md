# November 3 desktop refactor and wallpaper memory fixes

This source update publishes the November 2 refactor and the separate wallpaper
memory repairs. It builds on the November 2 music/GitHub widget publication;
those fixes and the existing integration opt-in gates are retained.

## Desktop configuration

- Settings tracks pointer movement through the asynchronous API. Output snapshots
  are cached until an output change, and usable-area updates target changed monitors.
- Settings and MateEngine idle IPC recreate failed socket instances.
- Hidden dock and disabled snow surfaces unmap; popup/Hermes animations reserve
  their final geometry and reveal content through the existing clip.
- Widget surfaces reuse a stationary procedural grain tile instead of drawing
  thousands of individual pixels whenever their canvas is repainted.
- Static wallpaper decoding uses image dimensions, crop, zoom, viewport and DPI.
  Transition capture textures exist only while needed. Failed images use the
  neutral fallback while preserving the saved wallpaper selection.
- Performance diagnostics are disabled by default. `Super+MouseForward` opens
  the existing screenshot editor on the current monitor.

The matching [ShojiWM pin](../sources.json) publishes decoration/cache fixes,
output-scoped layer redraws, SHM screencopy offset/bounds handling, title-update
cache reuse and side-button shortcuts. The existing lock-background API,
deadlock correction, output overlays, DPMS and MateEngine bridge are preserved.
Read [fork provenance](fork.md) before building or changing compositor versions.

## Wallpaper engine memory repairs

The private runtime builder now applies the NVDEC lazy-pool patch alongside the
existing mpv OpenGL-fence fix. Engine MPRIS/D-Bus polling and allocation fixes
remain included. The same repairs are published as an independent
[memory patch kit](https://github.com/howdeploy/linux-wallpaperengine/tree/fix/wallpaper-memory-20261103/contrib/wallpaper-memory).
See [the build and memory guide](wallpaper-engine.md) for pinned sources,
installation, historical evidence and limitations.

## Validation and installation boundary

The original refactor preparation recorded a native release build, 249 passing
Rust tests (two ignored), matching-SDK Deno checking and QML bytecode compilation.
The local configuration was subsequently installed, but graphical acceptance
and the new native binary's runtime were still outstanding in that handoff.
These historical results do not validate this sanitized source merge.

This publication checks source diffs, whitespace and staged files for private
data. It does not run tests, builds, lint, typechecks, installers, GUI checks or
new RAM/VRAM measurements. The NVDEC patch and combined public runtime recipe
need separate build/playback validation. Qt may still decode a full PNG
temporarily even when a smaller stored image is requested; no measured memory
reduction or guaranteed ceiling is claimed.

Use the existing [installation and recovery guide](install.md). Publishing these
commits does not install files, restart services or replace the running desktop.
