# Gamer Signal

> **Примечание по инструментам.** Скилл писался в среде Hermes: `web_search` / `web_extract` / `terminal` — её инструменты. В Claude Code / Codex используй аналоги: веб-поиск (Tavily / WebSearch), извлечение страниц (tavily_extract / WebFetch), shell (Bash). Логика скилла от рантайма не зависит.

Узкий skill для вопросов по играм, механикам, локациям, квестам, билдaм, настройкам, багам и патчам.

Главная идея: **лучше коротко сказать "не нашла подтверждения", чем придумать механику.**

## Когда использовать
- как пройти / где найти / как работает
- механика предмета, босса, навыка, квеста, NPC, локации
- изменилось ли что-то после патча
- есть ли актуальный способ/эксплойт/обход
- вопросы по Steam-версии, патчноутам, гайдам, обсуждениям

## Жёсткое правило источников

### Разрешённые источники (в порядке приоритета)
1. **Официальные источники**
   - официальный сайт игры / студии / издателя
   - официальные patch notes / changelog / support articles
   - Steam store/news/update posts от разработчиков
   - официальные manual / wiki / FAQ, если они реально официальные
2. **Steam Community**
   - Steam guides
   - Steam discussions
   - Steam announcements / news
3. **Разрешённые игровые базы и вики**
   - PCGamingWiki
   - wiki.gg
   - GameFAQs
   - StrategyWiki
   - fandom/wikia **только если нет более надёжного источника и это прямо помечено**

### Запрещённые источники по умолчанию
- общие SEO-гайд-сайты
- мусорные пересказы
- рандомные блоги
- AI-generated pages
- Reddit, YouTube, Discord-репосты, форумы вне allowlist — **не использовать для утверждений о механиках**, если пользователь отдельно не попросил расширить поиск

### Расширенный практический режим (только по явному запросу пользователя)
Если пользователь прямо просит расширить поиск ради практичного ответа по выживанию/тактике/прохождению, после исчерпания основных источников можно подключать:
1. YouTube-геймплей/гайды/short demos
2. Reddit-треды по конкретной механике
3. Нишевые форумы и обсуждения вне allowlist

Правила для этого режима:
- сначала всё равно проверить официальные источники / Steam / allowlist-вики
- чётко помечать, что это **community evidence**, а не официальное подтверждение
- не строить уверенные выводы на одном видео/комменте, если нет второго независимого подтверждения
- если видео без субтитров/транскрипта и есть только заголовок/описание, не пересказывать невидимое содержимое как факт
- practical survival tips (`убегай`, `держи свет`, `не триггери вблизи`) можно давать как fallback, но с пометкой, что это не строгая официальная механика

Если нормального подтверждения нет в разрешённых источниках — **не синтезируй ответ из воздуха**.

## Поисковой контур

### Базовый маршрут
1. Сначала пробуй `web_search` / Tavily через узкий запрос
2. Если выдача слабая или шумная — фолбэк на Brave/DuckDuckGo
3. Ищи **только по allowlist-доменам и Steam**

### Примеры запросов
- `site:store.steampowered.com/app OR site:steamcommunity.com/app GAME patch notes FEATURE`
- `site:steamcommunity.com/app GAME guide mechanic name`
- `site:steamcommunity.com/app GAME discussions mechanic name`
- `site:pcgamingwiki.com GAME setting crash fix`
- `site:wiki.gg GAME boss phase item`
- `site:gamefaqs.gamespot.com GAME quest item`

Если игра мультиплатформенная или имеет несколько редакций, добавляй:
- платформу (`PC`, `Steam Deck`, `PS5`, `Xbox`)
- edition (`Remastered`, `Definitive Edition`, `Director's Cut`)
- branch/version (`1.0.7`, `hotfix 3`, `Season 4`)

## Версионность и свежесть — обязательны

Перед ответом всегда пытайся понять:
- **о какой игре и какой именно версии речь**
- не относится ли найденная инфа к старому патчу
- не был ли гайд написан до ребаланса / DLC / rework / remaster
- не задал ли пользователь жёсткое окно свежести вроде `только 2026`, `только май`, `только после патча X`

Если пользователь явно ограничил свежесть источников, сначала ищи **только внутри этого окна** и не подмешивай старые гайды/обсуждения молча. Если свежих подтверждений нет, так и скажи. Переходить на старые источники можно только после явного согласия пользователя на практичный fallback.

### Что проверять
1. дату Steam guide/discussion
2. дату официальных patch notes
3. дату/версию страницы в вики, если видна
4. не конфликтует ли старый совет с новыми патчноутами

### Если версии конфликтуют
Отвечай только в таком духе:
- `По гайду от <дата> это работало, но после патча <версия/дата> подтверждения уже нет.`
- `Официальные патчноуты указывают изменение X, поэтому старый Steam-гайд может быть устаревшим.`

## Правило по механикам: никаких домыслов

### Разрешено говорить
- только то, что явно подтверждено источником
- осторожный вывод, если он основан на нескольких разрешённых источниках и не добавляет новых фактов
- `не нашла подтверждения`, `источники расходятся`, `инфа выглядит устаревшей`

### Запрещено
- допридумывать hidden mechanics
- объяснять причинно-следственные связи, которых источник прямо не утверждает
- смешивать данные из разных версий как будто они совместимы
- говорить уверенно там, где есть только один сомнительный гайд

## Минимальный рабочий процесс
1. Определи игру, платформу, версию/патч, если это можно вытащить из вопроса
2. Сделай **короткий smoke search** по официальным источникам / Steam
3. Если официального ответа нет — проверь Steam guides/discussions
4. Если всё ещё пусто — проверь allowlist-вики
5. Сверь даты и версии
6. Дай **короткий ответ без воды**
7. Приложи 1–4 источника

## Формат ответа
По умолчанию отвечай **очень коротко, последовательно и без раздутой структуры**. В игровых вопросах не дроби ответ на тяжёлые списки, подпункты и канцелярские блоки, если он отдельно не попросил. Предпочтительный формат — 3–6 коротких фраз или один компактный абзац: сначала что делать, потом следующий шаг, потом оговорка по источникам/версии.

Если пользователь **прямо просит краткий гайд по шагам / чек-лист**, тогда переключайся на простой формат `1. 2. 3.` без подпунктов и без длинных пояснений, чтобы было легко сверить пропущенный этап.

Базовый шаблон:

```text
Abiotic Factor, ориентир такой: открой X, потом пройди через Y, после этого используй Z. Если упрёшься в A, значит тебе ещё не хватило B. Источники старые/свежие: ...
```

Если нужны ссылки, добавляй их в самом конце отдельной короткой строкой `Источники:` без длинного оформления.

Если подтверждения нет:

```text
Прямого подтверждения в разрешённых источниках не нашла. Есть только более старые Steam-обсуждения/гайды, так что могу дать практичный маршрут с пометкой, что он не подтверждён свежими патчноутами.
```

## Приоритет ответов
1. Официальное подтверждение
2. Steam guide/discussion с датой и контекстом
3. Разрешённая игровая вики/база
4. Если свежего подтверждения нет, но пользователь явно согласен на практичный режим — можно использовать более старые Steam guides/discussions как **fallback**, но обязательно коротко и прямо помечать, что маршрут опирается на старые источники и может отличаться от текущего патча
5. Если ничего нет — честный отказ от выдумывания

## Практические оговорки
- Для сюжетных и локационных вопросов избегай спойлеров, если пользователь не просил прямо
- Для билдов/тактик отмечай, если это community recommendation, а не официальная механика
- Для багов и фиксов разделяй: `подтверждён разработчиком` vs `игроки сообщают`
- Для багов по сущностям/питомцам/триггерам отдельно проверяй **официальные Steam bug & patch threads** игры: они часто лучше всего показывают, это скрытая механика или реально сломанное состояние (`out of bounds`, disappearing, wrong form after relog, broken pathing, stuck in air). Если есть несколько независимых жалоб схожего типа, можно уверенно пометить проблему как systemic bug, даже если точный фикс не найден.
- Если вопрос про `работает ли сейчас`, почти всегда нужна сверка с последними патчноутами
- Если пользователь застрял в конкретной точке прохождения, сначала отвечай **только про ближайший блокер/следующий шаг**, не перескакивай через несколько этапов вперёд. Лучше коротко подтвердить текущую точку (`если эссенции уже вставлены, дальше маршрут такой...`), чем смешать в одном ответе прошлые и будущие стадии и запутать человека.
- Если пользователь прислал скриншот/цитату из внутриигрового журнала, письма или подсказки и спрашивает `что это значит` или `какой тут метод`, сначала **расшифруй саму подсказку буквально и коротко**. Не уводи ответ в соседние ветки прогресса, рецепты или общую теорию, пока пользователь не попросил связать это с полным маршрутом.
- Для Abiotic Factor отдельно помни, что журнал/compendium-подсказки могут уводить в сторону от непосредственного сюжетного блокера. Не привязывай рецепт или прогресс к лорной записи без второго подтверждения из Steam/official wiki.
- Для Abiotic Factor по T4 Keypad Hacker есть частый затык: рецепт открывается после письма про cleaning/storage в Security Sector, а не из любой тематически похожей записи журнала. Если пользователь видит серые материалы в рецепте, сначала различай `рецепт уже есть, но материалы ещё не подняты` vs `сюжетный порядок ещё не привёл к нужному дропу`, и отвечай именно на ближайший блокер вместо общих лекций про ингредиенты.
- Для Abiotic Factor по Reaper/IS-0059 не преувеличивай механику. Подтверждено: лазер/энергопистолет и X-ray воздействуют на него, могут выбивать Night Essence и временно отгонять/диспелить. Не подтверждай жёстко формулы вроде `если увидел первым — гарантированно спугнул`; если игрок уже детектнут, в Steam есть жалобы, что Reaper продолжает точно трекать цель. Разделяй `confirmed` и `practical inference` явно.
- Для Abiotic Factor по питомцам уже встречаются баги класса teleport / out-of-bounds / disappearance / electro-form weirdness. Если пользователь описывает зависшего в воздухе или неосязаемого pet companion, трактуй это в первую очередь как баг состояния питомца, а не как скрытую механику зоны, и отделяй подтверждённые workaround'и от неподтверждённых догадок.
- Для Abiotic Factor по Жнецу / Reaper не переуверяйся в формулировках. Подтверждено, что lasers / x-rays / "holy" damage его временно dismiss'ят и могут выбить Night Essence по кулдауну. Но из Steam также следует, что если он уже детектнул игрока, то может продолжать жёстко трекать позицию; не обещай механику в духе `если заметил первым, гарантированно безопасно спугнёшь`. Более честная формулировка: ранний детект даёт больше шансов первым дать лазер/рентген, но это не железобетонная гарантия безопасного контроля.
- Для Abiotic Factor по свету и Жнецу различай `свет как инструмент игрока` и `свет как триггер агра`. Official wiki указывает, что фонарик нужен игроку для ориентирования и light sources flicker рядом с Жнецом; не утверждай без подтверждения, что Жнец буквально приходит на фонарь или что NVG делает игрока невидимым.
- Для Abiotic Factor по Flathill/мёду помни несколько подтверждённых ориентиров. Портал в Flathill находится в Office Sector: с 2 этажа на 3-й лифтом, дальше прямо, затем вниз к зоне Silo 3 / рядом с Break Room и viewing area. По ульям не обещай 100% спавн в конкретной точке: Steam указывает, что у hive есть несколько spawn spots и они не гарантированы каждый заход.
- Для Abiotic Factor по Beekeeper Suit не путай его с найденным Hazmat Suit. Подтверждено по wiki snippets: Beekeeper Suit крафтится из `Hazardous Materials Suit x1 + Leather Scrap x4 + Plastic Scrap x4 + Giga Glue x4`. Если пользователь уверен, что «видел костюм пчеловода», чаще всего он вспоминает именно Hazmat Suit.
- Для Abiotic Factor по Hazmat Suit есть практичный надёжный fallback-ориентир из Steam: один респавнится в Flathill на кузове грузовика и возвращается после reset portal world. Ещё игроки пишут о редком дропе suit с Lab Rats, но это менее надёжный путь — в ответах лучше рекомендовать Flathill truck как основной practical route.
- Для Abiotic Factor по Beekeeper Suit держи в уме свежо подтверждённое: он не выглядел как trade item в доступных wiki snippets и надёжного подтверждения покупки у торговцев нет; practical default answer — считать, что он крафтится, а не покупается. Подтверждённый рецепт по wiki snippet: `Hazardous Materials Suit x1 + Leather Scrap x4 + Plastic Scrap x4 + Giga Glue x4`.
- Для Abiotic Factor по ульям/пчёлам уже подтверждено из Steam: для безопасного лута нужен Beekeeper Suit; без него можно выживать через резисты/броню, но это fallback. В first anteverse / Flathill hive spawn не гарантирован каждый заход. Для вскрытия hive полезно советовать Vacuum, потому что игроки жалуются, что дроп со склонов и в anteverse легко улетает в void.
- Для Abiotic Factor по уже скрафченному Beehive не путай `где взять мёд` с `почему база-улей не работает`. По wiki snippet Beehive расходует `10 ml of Antejuice per production cycle`; practical default answer — ставить рядом бочку с Antejuice. В Steam есть сообщения, что просто antejuice pool/лужа может работать ненадёжно, так что как надёжный совет давай именно barrel near hive, а не `поставь у любой лужи`.
- Если пользователь говорит про русскую локализацию и пишет `антесок`, отвечай этим названием или как минимум `антесок (Antejuice)`, а не выпрямляй ответ в чисто английские термины.
- Для игровых ответов по умолчанию держи формат реально коротким: 1 короткий абзац или 3–5 коротких строк. Если ушла в длинное объяснение, лучше ужать до `что делать сейчас` + 1 оговорка по источникам.

## Эксплуатационные заметки по источникам
- `wiki.gg` may отдавать Cloudflare block для `web_extract`, `terminal` и прямого `requests/curl`, даже если страница видна в поисковых сниппетах. В таком случае не пересказывай сниппет как полноценное подтверждение, а опирайся на Steam discussions/news или другие разрешённые источники, где текст реально удалось извлечь.
- Для Abiotic Factor есть полезный частный приём: точечный запрос вида `site:abioticfactor.wiki.gg/wiki "ITEM" "Recipe" "Abiotic Factor"` нередко вытаскивает в сниппете сами ингредиенты рецепта, даже когда полная страница заблокирована Cloudflare. Это годится как осторожное подтверждение именно состава рецепта/used in, но не как подтверждение всей остальной механики страницы.
- Steam guides нередко плохо вытаскиваются в текст или могут быть помечены как incompatible/removed. Если тело гайда не извлеклось, не делай вид, что прочитала его — лучше переключись на Steam discussions с accepted answer/цитатами и на патчноуты.

- Если `web_extract` по Steam discussion возвращает почти одну оболочку страницы, можно вытянуть текст через `terminal` + `requests` и искать в HTML сериализованные комментарии/цитаты. Это особенно полезно для фраз вроде `above the toilets`, `computer`, `attachment`, `mushroom portal`, `Thule`, когда сниппет в поиске есть, а нормальный extract молчит.
- По trade-шаблонам и сниппетам не угадывай направление обмена. Если в сниппете просто видны `Chain`, `Ammo`, числа и unlock-условия, этого недостаточно, чтобы утверждать `у NPC можно купить цепи` или `NPC покупает цепи`. Нужна явная вторая опора: полный текст таблицы, отдельная страница предмета/NPC, или Steam-обсуждение с прямой формулировкой.
- Если направление трейда не подтверждено, лучше честно сказать `вижу, что Chain фигурирует в trade template, но не могу надёжно подтвердить, это цена или выдаваемый товар`.
- Если пользователь спрашивает по-русски и явно играет с русской локализацией, по умолчанию отвечай через русские названия предметов, локаций, квестов и интерфейсных терминов. Не строй ответ вокруг английских имён, если смысл можно передать по-русски.
- Если прямой текст локализации недоступен, ищи русские Steam-сниппеты/руководства и используй только те формы, которые там реально видны.
- Если подтверждённого русского варианта не нашлось, сначала используй естественное русское описание предмета/функции (`костюм химзащиты`, `костюм пчеловода`, `верстак`, `улей`), а английское название давай только как уточнение в скобках, если это реально помогает сверке.
- При ответах про конкретный затык сначала давай короткий практический вывод на русском, а уже потом, при необходимости, уточняй англоязычный термин. Не отвечай так, будто пользователь играет в английскую версию, если он явно напомнил про русскую локализацию.

## Короткий self-check перед финалом
- Я опираюсь только на разрешённые источники?
- Я указала версию/дату или честно сказала, что она неясна?
- Я не выдумала механику между строк?
- Если источник спорный, я это явно пометила?

Если хоть на один пункт ответ `нет` — не делай уверенного утверждения.
